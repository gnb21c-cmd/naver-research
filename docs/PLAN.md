# 네이버 고객 집계 — 설계 (2026-10-13 시작)

## 1. 목적 (사장님 지시)
1. 기간을 정하면 그 기간 동안 **이용완료**한 손님의 정보를 모은다.
2. 모은 정보를 사장님이 정하는 **구분 기준 · 항목**별로 집계한다.
3. 시간이 걸려도 기간 전체를 모은다.
4. PC 에 저장되어 분석할 수 있게 자료화한다 (엑셀).
5. 배포 · 설치형이 아니라 **사무실 PC 한 대 · 책임자 1명(사장님)** 이 쓴다.

## 2. 흐름 (체험판에 들어 있는 것)
1. **수집** — 기간(바로 고르기: 지난달 · 최근 3개월 · 입장료로 바뀐 뒤 · 2026년 · 2025년 · 전체) → [수집 시작]
   - 날짜마다 네이버 예약현황 → 이용완료가 있는 회차 → 완료자 목록을 읽음
   - 하루씩 PC 에 바로 저장 → 멈추거나 꺼져도 다음에 이어 받기, 이미 받은 날은 건너뜀 ([이미 받은 날도 다시 받기] 선택)
   - 못 읽은 칸이 있는 날은 '실패'로 두고 끝에 한 번 더
   - 실제 속도 예상: 하루 20 ~ 40초 (1년 ≈ 2 ~ 4시간)
2. **고객 자료** — 방문 건별(이용일 · 회차 · 상품 · 예약번호 · 이름 · 전화 · 누적 이용완료 · 신규/재방문) / 고객별(기간 안 방문 · 첫 · 마지막 방문 · 누적 이용완료 · 휴일 비율 · 자주 온 회차), 찾기 · 쪽 넘기기
3. **구분 기준** (켜고 끄기 · 구간 글로 고치기)
   - 고객 기준: 기간 안 방문 횟수(`1, 2-3, 4-9, 10+`) · 누적 이용 횟수(`1, 2-5, 6-20, 21+`)
   - 방문 기준: 신규 · 재방문(그 방문이 첫 이용완료) · 평일 · 휴일 · 요일 · 시간대(`10-12, 12-14, 14-17, 17-20`) · 상품 · 월별 · 기간 스티커(보고 앱 설정과 같은 규칙) · 요금제(2026-04-01 전 교환권 / 뒤 입장료)
   - 교차표: 줄 기준 × 칸 기준, 숫자 = 방문 건수 또는 고객 수(합계는 같은 손님 한 번)
4. **집계 결과** — 요약(방문 건수 · 고객 수 · 1명당 방문 · 신규 방문 비율 · 2번 이상 온 고객) + 켠 기준마다 표 + 교차표
   - 방문 기준 표의 고객 수는 그 구분에 한 번이라도 온 손님 수라 더하면 전체보다 많을 수 있음 (화면에 밝힘)
5. **엑셀 받기** — 시트: 설정 · 방문 건별 · 고객별 · 기준별 집계 · 교차표. 실제 프로그램은 저장 폴더에 바로 저장 · 암호 선택
6. **설정 · 보안** — 책임자 · 저장 폴더 · 전화/이름 가운데 가리기(화면 · 엑셀) · 프로그램 암호 · 엑셀 암호 · 보관 기간(12/24/36개월) 지난 원자료 지우기(두 번 눌러야)

체험판 검증(2026-10-13): 수집 흉내 끝까지 → '모두 받음', 표마다 방문 건수 합 = 전체 · 교차표 합계 = 전체, 엑셀을 열어 방문 · 고객 수와 고객별 방문 합 일치 · 가리기 적용 확인, PC · 폰 · 어두운 화면 넘침 없음.

## 3. 아직 정할 것 (사장님께 여쭤볼 것)
1. 사무실 PC — POS 메인 PC 와 다른 PC 인지, Windows 인지
2. 모을 고객 정보 — 완료자 목록 · 예약 상세에 보이는 것 중 무엇 (인원 · 요청사항 등 더 있는지), 화면 캡처(이름 · 번호 가려서)
3. 구분 기준 · 항목 — 체험판 기준에 더하거나 뺄 것
4. 네이버 화면에 예약 목록 '엑셀 다운로드' 버튼이 있는지 — 있으면 그 파일을 자동으로 받아 쓰는 게 더 빠르고 정확
5. 프로그램 형태 — 통합데스크(astanakiz desk)와 같은 Windows 프로그램(설치 없이 실행 파일 하나 권장) 또는 폴더 + 더블클릭 실행
6. 네이버 아이디 · 비밀번호 — 사장님은 Firebase 에 등록한 것 같다고 함(확인 못 함). 이 프로그램은 쓰지 않음. 클라우드에 비밀번호가 있다면 지우고 네이버 비밀번호를 바꾸길 권함

## 4. 개인정보 원칙
- 프로그램 · 자료는 사무실 PC 한 대에만. GitHub · Firebase 에 올리지 않음
- 네이버 비밀번호 저장 안 함 (직접 로그인 → 로그인 상태만 그 PC)
- 내부 분석에만 사용 (문자 · 광고는 별도 동의 필요할 수 있음)
- 엑셀을 남에게 줄 때는 가리기를 켜고 만든 파일만

## 5. 가져다 쓸 수 있는 것 (`gnb21c-cmd/Report`, 공개)
- `apps/collector/src/naverBook.ts` — 네이버 예약관리 열기 · 날짜 이동(`gotoDate`) · 회차 칸 읽기(`readCells`) · 완료자 목록 읽기(`readList`: 예약번호 · 손님 · '완료 N') · 화면 구조 살피기(`probe`, 숫자는 9 로 가림)
- `apps/collector/src/naver.ts` — 자동 수집 흐름 · 못 읽은 칸 끝에 다시 · 확인만(dry) 모드
- `packages/core/src/naverAuto.ts` — 상품 이름 가리기(`isNaverTicketProduct`: '~26.3.31 …' 지난 상품 제외), 회차 시각(`naverTime`), 신규방문자 계산
- `apps/collector/naver-login/login.mjs` — 사람이 한 번 로그인해 state.json 저장하는 창
- 통합데스크(`gnb21c-cmd/astanakiz`)는 Windows 프로그램(Electron) · 설치본은 GitHub Releases · 비밀번호는 그 PC 에만 Windows 암호화
- '완료 N' 은 손님 아이디를 따라가는 **누적** 이용완료 건수 — 지난 날짜를 지금 읽으면 그날 당시 값이 아니라 지금까지 값일 수 있음 → 실제 화면으로 확인 필요 (신규/재방문 판단에 영향)
